## 알아두면 시간 아끼는 것들

`middleware`**가 아니라** `proxy`**.** Next 16이 `middleware` 파일 규약을 deprecate하고
이름을 바꿨습니다. API는 같습니다. Supabase 공식 문서는 아직 `middleware`로 적혀 있으니
문서를 볼 때 헷갈리지 마세요.

**세션 판정은** `getClaims()`**.** `getSession()`은 서버에서 신뢰하지 않습니다.

**anon 키는 publishable key(**`sb_publishable_...`**)를 씁니다.**
환경변수 이름은 기획서 §9대로 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 유지.

**익명 키로 테이블을 조회하면** `200 []`**가 정상입니다.** 정책이 전부
`to authenticated`라 RLS가 아무것도 주지 않습니다. 행을 눈으로 보려면
`service_role` 키가 필요한데, `supabase projects api-keys`는 새 `sb_secret_...`을
마스킹해서 줍니다 — 레거시 `service_role` JWT를 쓰거나 대시보드에서 복사하세요.

**쿼리 문법만 확인할 때는 익명 키가 오히려 편합니다.** RLS로 `[]`가 오지만 문법이
틀리면 400이 옵니다. **임베드한 필터가 정말 자식 테이블에 걸리는지**도 없는 컬럼을
넣어보면 압니다 — `passage.nope=is.null` → `column passage_1.nope does not exist`.

**Supabase가 실제로 들고 있는 OAuth 값 확인법.**

```
GET {SUPABASE_URL}/auth/v1/authorize?provider=google&redirect_to=...
→ 302 Location에 client_id, redirect_uri, scope가 그대로 들어 있음
```

세션 1-c에서 구글 client ID가 앞부분(`1974351245-`)이 잘린 채 저장돼 있어
`invalid_client`가 났습니다. 구글 client ID는 항상
`프로젝트번호-무작위문자.apps.googleusercontent.com` 형태입니다.

`toy` **프로젝트를 가리키고 있지 않은지 확인.**
`cat supabase/.temp/project-ref` → `ccfgjaxaylwwdfsspdys`

**로그인이 필요한 경로를 스크립트로 검증하는 법.** 구글 OAuth는 스크립트로 못
돌리지만, 검증용 계정을 만들면 됩니다. 세션 3에서 API 전체를 이렇게 확인했습니다.

```
1. service_role로 계정 생성   POST /auth/v1/admin/users  {email, password, email_confirm:true}
2. 비밀번호로 로그인          POST /auth/v1/token?grant_type=password   → access_token
3. 쿠키로 만들어 curl에 붙임  sb-<project-ref>-auth-token=base64-<base64(세션 JSON)>
4. 끝나면 계정 삭제           DELETE /auth/v1/admin/users/<id>
```

`shelf_item`·`profile`은 `auth.users` cascade로 같이 사라지고 `book`은 남습니다
(공용 마스터라서 정상입니다). `UID`**를 셸 변수 이름으로 쓰지 마세요** — zsh 예약
변수라 대입이 실패합니다.

**공개 버킷은 CDN이 캐시합니다.** 같은 경로에 파일을 덮어써도 공개 URL이 한동안
옛 파일을 줍니다. 세션 3에서 이걸 모르고 버그로 착각했습니다. 실제 내용을 보려면
인증 경로(`/storage/v1/object/cover/...` + service_role)나 쿼리스트링으로 캐시를
피하세요.

`supabase db dump`**는 도커가 필요합니다.** 적용된 스키마를 원격에서 대조할 때는
Management API의 query 엔드포인트로 직접 조회하세요 (세션 2에서 그렇게 했습니다).

**Next 16** `dev`**는 데몬으로 뜹니다.** 실행한 명령이 먼저 끝나고 서버는 남습니다.
두 번 실행하면 `Another next dev server is already running`과 함께 PID를 알려줍니다.
로그는 `.next/dev/logs/next-development.log` (브라우저 콘솔 경고까지 들어옵니다).
`pkill -f "next dev"`**는 이미 떠 있던 서버까지 잡습니다** (세션 4에서 한 번
그랬습니다). 포트로 골라 죽이세요.

`next/font`**로 한글 폰트를 쓸 때** `subsets`**를 지정하면 안 됩니다.** next/font가 아는
서브셋은 `latin` / `latin-ext`뿐입니다. 지정하면 **빌드는 통과하고 한글만 시스템
폰트로 조용히 떨어집니다.** 비워두면 한글 서브셋까지 내려받습니다 — 대신
unicode-range가 246개로 쪼개지므로 `preload`는 끕니다.

## 판단 기록

무엇을 만들었는지는 커밋과 코드 주석에 있습니다. 여기 남기는 건 **왜 그렇게
했는지**입니다.

### 세션 1 · 1-b · 1-c — 스켈레톤과 인증

`create-next-app` 잔여물(Geist 폰트, 다크 모드 CSS, `public/*.svg`, 생성된
`CLAUDE.md`·`AGENTS.md`)을 걷어내고 design.md §색의 6개 토큰만 Tailwind `@theme`에
심었습니다. **다크 모드는 두지 않았습니다 — 종이는 한 색입니다.**

공개 경로는 `/`, `/auth/*`, 정적 파일뿐이고 나머지는 전부 보호됩니다.
`/auth/callback`의 `next` 파라미터는 `/`로 시작하고 `//`로 시작하지 않는 것만
허용합니다 (오픈 리다이렉트 방지).

`profile`에 insert/delete 정책을 두지 않았습니다 — 행을 만드는 건 가입 트리거뿐이고
삭제는 `auth.users` cascade로 일어납니다.

**공용 프로젝트** `toy`**를 접고 전용 프로젝트로 간 이유.** 같은 판단을 다시 할 일이
있을 수 있어 남깁니다.

1. `db push`**가 아예 막힙니다.** `supabase_migrations.schema_migrations`가
   프로젝트 단위로 공유되는데, 원격에 checkin 이력 19개가 있고 로컬엔 없습니다.
   CLI가 제안하는 `migration repair --status reverted`는 checkin 이력을 전부
   "되돌림"으로 표시하는 명령이라 돌리면 안 됩니다
2. `auth.users` **트리거 이름이 전역입니다.** `on_auth_user_created`는 Supabase
   공식 문서 예제 이름이라 checkin도 쓸 가능성이 높고, `drop trigger if exists`가
   남의 가입 트리거를 조용히 지웠을 겁니다
3. **리전.** `toy`는 Mumbai라 기획서 §9(Seoul)와 어긋났습니다
4. **기존 사용자에게 트리거가 안 걸립니다.** `auth.users`가 공유되면 checkin으로
   먼저 가입한 사람은 이미 행이 있어 `insert` 트리거가 발동하지 않습니다

옮기면서 잠깐 넣었던 `moseori_` 프리픽스도 전부 걷어냈고, 리전 어긋남과 백필
코드도 함께 사라졌습니다.

### 세션 2 — 데이터 모델과 RLS

1. `review`**의 UNIQUE와 soft delete가 충돌합니다.** 컬럼 제약으로 걸면 지운 리뷰가
   자리를 차지해 같은 책에 다시 못 씁니다. → **부분 UNIQUE 인덱스.** 실제로
   지키려는 규칙은 "살아있는 리뷰가 책당 하나"입니다
2. `book`**의 NOT NULL은 셋뿐입니다** (`aladin_item_id` / `title` / `created_at`).
   `cover_path`·`accent_color`는 알라딘 응답 직후에 값이 없습니다
3. `review.updated_at`**은 앱이 갱신합니다.** §6이 상태 전이를 애플리케이션
   레이어에서 처리한다고 정했으므로 같은 방침 — DB 트리거를 두지 않습니다
4. **FK 삭제 동작** (§4에 없어서 정함): `user_id` → cascade /
   `shelf_item.book_id` → **restrict**(공용 마스터라 남의 기록이 참조 중일 수 있음) /
   `review`·`passage`의 `shelf_item_id` → cascade (§4: `shelf_item`은 hard delete) /
   `passage_comment.passage_id` → cascade
5. `book`**의 delete 정책을 만들지 않았습니다.** RLS가 켜져 있으므로
   정책 없음 = 아무도 못 지움. 의도한 결과입니다
6. **인덱스는 최소한만.** §4 정렬 규칙과 §6 오늘의 밑줄에 맞춘 것뿐.
   pgroonga는 enable만 하고 인덱스는 §8대로 만들지 않았습니다

**대조하며 알게 된 것:** 부분 인덱스는 `pg_constraint`가 아니라 `pg_indexes`에
잡힙니다. `(shelf_item_id, page nulls last, created_at)`은 Postgres가
`(shelf_item_id, page, created_at)`로 정규화합니다 — btree ASC 기본이 이미
NULLS LAST라 동작은 같습니다.

### 세션 3 — 알라딘 연동과 책 담기

1. **큰 표지는** `/coverbig/`**가 아니라** `/cover500/` (물어보고 진행).
   CLAUDE.md의 "200px가 최대"와 부딪혀서 물었고, **원본은 500px로 저장하되 표시
   크기는 design.md 그대로**로 정했습니다
2. **대표색은 색조만 표지에서 가져옵니다.** 24×24로 줄여 채널당 4비트로 뭉갠 뒤
   흰 여백(L>95%)과 검은 글자(L<8%)를 빼고 최다 덩어리를 고릅니다(채도 가중).
   §3이 명도와 채도를 강제하므로 실제로 고르는 건 색조뿐입니다. 그 이상 정교해질
   이유가 없습니다
3. **§3 정규화 범위를 1%씩 안으로 넣은 이유.** 16진수로 저장하면 채널이 8비트로
   뭉개집니다. 명도 90% 근처에서는 채널 차이가 `6~7`밖에 안 돼 반올림 한 번에 채도가
   2%p씩 튑니다. `88~91` / `15~30`을 그대로 쓰면 **저장된 색을 다시 재봤을 때** 규칙을
   벗어납니다 (18권 중 5권). → `88.5~90.5` / `16~29`로 클램프
4. **검색 캐시는 테이블이 아니라 Next Data Cache입니다.** URL이 그대로 캐시 키라서
   §7의 "몇 시간 캐시"에 테이블이 필요하지 않습니다. 검색어는
   trim·공백축약·소문자로 정규화해 적중률을 올립니다
5. **이미 있는** `book`**의 사실 정보는 다시 쓰지 않습니다.** 알라딘 응답이 바뀔 이유가
   거의 없고, 남이 담아둔 행을 매번 덮어쓰면 write만 늘어납니다. 예외는
   표지입니다 — `cover_path`나 `cover_width`가 비어 있으면 이번에 채웁니다
6. **표지 실패가 담기를 실패시키지 않습니다.** §4에서 nullable입니다.
   비어 있으면 다음에 이 책을 담는 사람이 다시 시도합니다
7. **이미 서재에 있는 책은 상태를 덮어쓰지 않습니다.** 담기는 새로 담는 동작이고
   상태 변경은 책 상세에서 하는 일입니다
8. **동시 삽입.** 두 사람이 같은 책을 같은 순간에 담으면 `book`의 UNIQUE가 터집니다.
   `23505`면 그 행을 다시 읽어 씁니다
9. **판형은 표지 이미지의 방향을 심판으로 씁니다.** 이미지가 세로형이면 판형의 큰
   값이 세로, 가로형이면 작은 값이 세로. 진짜 가로형 책은 이미지도 가로형이라
   그대로 남고 잘못된 값만 바로잡힙니다. 정사각형에 가까운 책(±4%)은 손대지
   않습니다. 가로로 긴 책이 실재하는 건 문제가 아닙니다 — **그건 그대로 보여주는 게
   맞습니다.** 문제는 알라딘이 어느 값이 세로인지를 틀리게 준다는 것입니다.
   알라딘이 준 값은 `book`에 원본으로 남기고 **보정은 화면에서만** 합니다
10. **검색 결과 표지는** `next/image`**를 쓰지 않습니다.** 아직 담지 않은 책은 표지의
    실제 픽셀을 모르는데 `next/image`는 `width`·`height`를 요구합니다. 아무 값이나
    적으면 비율이 틀려 개발 콘솔에 경고가 쌓입니다(실제로 쌓였습니다).
    담긴 뒤에는 크기를 알고 있으니 `/shelf/[id]`는 실제 비율을 씁니다
11. **미인증** `/api/`**\*는 401이 아니라 307입니다.** `proxy.ts`가 전 경로를 보호하므로
    라우트의 401 분기까지 오지 않습니다. 그대로 두었습니다 — 브라우저에서는
    이게 맞습니다

**지켜야 하는 두 가지.** `ALADIN_TTB_KEY`를 읽는 곳은 `lib/aladin/client.ts`
**하나뿐입니다** — CLAUDE.md 절대 규칙입니다. 표지 버킷 `cover`의 정책은 `book`과
같은 모양(전체 read / 인증 insert · update)이고 **delete 정책은 없습니다.**
표지도 공용 마스터라서입니다.

**백필 1건.** 마이그레이션 전에 브라우저에서 담긴 『달리기를 말할 때 내가 하고 싶은
이야기』가 `cover_width`가 비어 있어서 Storage의 표지를 읽어 500×714로 채웠습니다.

   화면이라 쪽수만. 배경은 그 책의 accent 하나뿐이라 같은 색 카드가 이어집니다
5. **MaruBuri 출처** — 구글 폰트에 없어 `fonts-archive/MaruBuri`의 Regular woff2
   (276KB, `wOF2` 확인)를 `src/app/fonts/`에 self-host. design.md대로 400 한 무게.
   Plex의 무-subset·`preload:false` 방침을 그대로 따랐습니다
6. **`ScribbleLine`에 `animate`/`delay` 추가** — dashoffset 0.7s 그어짐(reduced-motion
   감쌈). 네비 활성 표시는 끕니다(페이지마다 다시 그어지면 산만). design.md §모션의
   "카드가 나타날 때 밑줄이 그어진다"가 여기서 실현됩니다

**어긋난 것:** 새 의존성 없음(폰트는 `next/font` 내장 + self-host 파일 하나).
에디터 라이브러리 안 붙임(§6). 책 상세 제목 크기(19px)·별점 UI(별)는 design.md에
규격이 없어 임시로 정한 값입니다.

**검증:** `lint`·`build`(전 라우트 타입체크) 통과, `dev` 부팅·미인증 307 확인.
**상호작용(별 클릭→서버 액션, 손그림 그어짐, sticky 폼, 리뷰 굵게)은 구글 OAuth +
실제 데이터 뒤라 자동 구동 못 했습니다** — 로그인해서 한 번 돌려보는 게 남았습니다.

### 세션 6 — 밑줄 목록 `/underlines`과 문장 카드

**밑줄 입력은 세션 5에 이미 있었습니다**(`add-passage.tsx`가 §6 만족). §5상 입력은 책
상세의 일이라 여기선 **목록만** 만들었습니다.

- **문장 카드를 공용화**(`app/passage-card.tsx`). 선택 prop 셋만 더함 — `source`(출처=
  책·작가, 목록에서만), `href`(카드 전체를 그 책 상세로), `draw`.
- **출처는 작가만.** `book.author`는 알라딘 원문(`… (지은이), … (옮긴이)`)이라
  옮긴이·그림·감수를 떼고 지은이만 뽑습니다(`lib/books/author.ts`). 원문은 `book`에
  그대로, **표시할 때만** 골라냄 — §4 "파싱 없이 원문 저장"과 어긋나지 않음. 책 상세의
  서지 정보는 전체 크레딧 유지. 지은이 역할이 없으면(전부 옮긴이 등) 첫 이름을 역할만
  떼고 폴백.
- **코멘트 층은 세로선 대신 여백**으로 나눔(design.md 허용 두 방식 중 시안이 택한 쪽).
- **섞기 제외**(사용자 지시). **정렬 최신순**, **아카이브 포함**(§5가 제외 명시 안 함),
  **빈 상태 문구는 §3 톤**으로 지음.
- **손그림 선(시안 `밑줄.png`에 맞춤).** 카드 등장에 그어지는 연출을 **안 씁니다** —
  목록·상세 모두 처음부터 완성된 전폭 정적 선. (사용자가 본 "짧은 선"은 0.7초 draw를
  도중에 캡처한 것이고 선은 이미 전폭이었음.) 파형은 폭÷~160px 다-마디 물결을
  Catmull-Rom으로 잇고, 문장↔출처를 가르는 구분선이라 폭 끝까지 이어짐. 진폭 마디점
  ±2.5 / 끝점 ±2, 높이 12(한때 ±4/±3까지 키웠다 지저분해 줄임). 네비 활성 표시는 폭이
  짧아 1마디라 담백. 그어지는 코드(`ScribbleLine animate`)는 저장 완료 순간용으로 남김.

**검증:** `lint`·`build` 통과. 임베드 쿼리(`passage→shelf_item→book`)·저자 파서 확인.
**카드 실렌더는 헤드리스 크롬 + 임시 공개 페이지(`/auth/*`, 확인 후 삭제)로 확인** —
svg가 카드 폭 전체(604px), draw 끈 상태에서 로드 직후부터 전폭
(`--virtual-time-budget`으로 애니메이션 프레임 제어). 로그인 뒤 실데이터 렌더만 남음.

### 세션 7 — 오늘의 밑줄 · 빈 상태 · 모바일 · reduced-motion

브랜치 `feat/todays-underline`.

1. **오늘의 밑줄 선택**(`lib/underline/today.ts`) — §6의 "하루 고정(시드 결정적)"과
   "오래 안 본 것 우선"이 부딪히는 지점을 이렇게 풀었습니다. 골라서 `last_shown_at`을
   찍으면 후보 풀이 달라져 새로고침 때 다른 걸 고르게 됩니다. → **오늘 이미 보여준
   밑줄이 있으면 그걸 그대로 다시** 보여주는 short-circuit이 하루 고정을 지키고,
   시드(`user_id:날짜`)는 "그날의 첫 선택"만 결정합니다. 후보 풀은 **오래 안 본 절반**
   (`last_shown_at` nulls first → created_at 정렬 후 앞 `ceil(len/2)`), 그 안에서
   `FNV(user_id:날짜) % 풀크기`로 고름. 인덱스 안정성을 위해 풀은 불변값(created_at)로
   재정렬. 날짜 경계는 **Asia/Seoul**(서버 UTC라 명시 안 하면 자정이 9시간 어긋남).
   → 로직은 6케이스로 검증(3개 미만 null / 동일 입력 동일 출력 / 유저별 상이 /
   stale 절반 안에서만 / 오늘 본 것 재노출·미갱신 / KST 경계).
2. **서버 렌더 중 `last_shown_at` 쓰기.** RSC 렌더에서 쓰는 건 이상적이진 않지만,
   short-circuit 덕에 **사용자당 하루 1회뿐**이고 시드가 결정적이라 동시 로드에도
   idempotent합니다. 그래서 허용했습니다. `user_id`는 시드로만 쓰이고(보안은 RLS)
   `getClaims().sub`로 가져옵니다.
3. **3개 미만이면 아무것도 안 보임**(사용자 지시). §6은 "밑줄을 그어보세요" 안내를
   요구하지만 두지 않습니다. 빈 서재(0권)는 §5대로 오늘의 밑줄 자리 자체가 없음 —
   `/shelf`가 `empty`일 때 컴포넌트를 렌더하지 않음.
4. **카드는 teaser + 링크**(사용자 결정). 문장→손그림선→출처(책·저자·쪽수)만,
   코멘트는 접음. 카드 전체가 그 책 상세로. `PassageCard`에 `today` prop 추가 —
   여백 34/32/28·문장 22px만 바꾸고 나머지 구성은 문장 카드와 동일(design.md §오늘의
   밑줄). 배경은 그 책 accent_color(§5).
5. **빈 상태 점검** — 랜딩(해당없음)·책장 빈 서재(검색창만)·탭 빈 곳("여기엔 아직
   없습니다")·책 상세 밑줄 없음·밑줄 목록 빈 문구, 전부 이미 있고 §3 톤 일관. 새로
   만들 빈 상태는 오늘의 밑줄뿐. `/archive`·`/settings`는 화면 자체가 없어 범위 밖.
6. **모바일 점검** — 컨테이너·여백·격자·sticky 입력은 규격대로. 유일하게 손댄 곳:
   **상태 탭**이 좁은 화면(안쪽 335px)에서 4탭+개수로 살짝 넘칠 수 있어 줄바꿈 대신
   **가로 스크롤**(음수 마진으로 여백까지 흘리고 스크롤바 숨김). "수평 나열"을 지키면서
   페이지가 옆으로 밀리지 않게. 상세의 상태 줄은 이미 `flex-wrap`이라 그대로.
7. **reduced-motion** — 앱의 유일한 모션 `.scribble-draw`는 이미 `no-preference`로
   감싸져 있고, 오늘의 밑줄 카드는 정적(`draw={false}`)이라 **새로 넣은 모션이 없음**.
   투기적 CSS는 추가하지 않음.

**검증:** 선택 로직 6케이스 통과, `lint`·`build`(전 라우트 타입체크) 통과.
**오늘의 밑줄 실렌더·모바일 상태 탭 스크롤은 로그인 세션이 있어야 보여 아직 눈으로
못 봄**(OAuth 게이트, 세션 5·6과 같은 제약). 로그인해서 한 번 돌려보는 게 남음.
