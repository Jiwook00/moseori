# 모서리 · 기획서

> 이 문서는 구현(Claude Code)에 넘기기 위한 기획서입니다.
> "안 하는 것" 목록이 명시되어 있습니다. 여기 없는 기능은 만들지 마세요.

---

## 1. 개요

**이름:** 모서리 — 접어둔 페이지 모서리에서.

**한 줄:** 읽은 책을 기록하고, 좋았던 문장에 밑줄을 긋는 웹.

**만드는 이유.** 기존 독서 기록 앱들은 기능이 너무 많거나, 디자인이 마음에 안 들거나,
유료 광고가 거슬립니다. 원하는 건 "읽은 책을 기록한다"는 본질입니다.
책을 읽으며 좋았던 문장을 페이지 번호와 함께 적고, 그때의 느낌과 왜 수집했는지를
같이 남기는 습관이 있는데, 지금까지 노션으로 하던 걸 전용 도구로 옮기는 것입니다.

**성격.** 나를 위해 만들지만 나만 쓰는 앱은 아닙니다. 구글 로그인으로 누구나 쓸 수 있고,
지인에게 추천할 수 있는 정도. 홍보나 상업화 의도는 없습니다.

**방문자가 느꼈으면 하는 것**

- 심플하다
- 바로 시작해 볼 수 있겠는데?
- 어렵지 않다
- 기록하는 재미가 있겠다
- 내가 읽은 책들이 보일 때 기분이 좋다

## 2. 범위

### 1차

- 구글 로그인
- 알라딘 API로 책 검색 → 서재에 담기
- 책 상태 관리 (읽고 싶음 / 읽는 중 / 읽음 / 덮어둠) + 아카이브
- 5점 별점
- 리뷰 작성 (책당 하나, 최소 서식)
- 밑줄 수집 (문장 + 쪽수) 및 밑줄에 코멘트 달기 (여러 개)
- 밑줄 전체 모아보기
- 오늘의 밑줄 (책장 맨 위)
- 책장에 책별 밑줄 개수 표시
- 계정 삭제, 데이터 내보내기

### 2차

- **큐레이션 홈** — 책과 그 책의 밑줄·코멘트·리뷰가 함께 놓이는, 잘 큐레이팅된
  독립 서점 웹페이지 같은 화면. 내가 읽고 내가 쓴 것인데도 "이 책 읽고 싶다"는
  감정이 들게 하는 것이 목표. `/`가 이 화면이 되고 책장은 `/shelf`에 남습니다.
- 통합 검색 (§8)
- 알라딘에 없는 책 직접 입력해서 추가
- 다 읽은 순간 되돌아보기 (완독 시 그 책의 밑줄을 펼쳐 보여주고 리뷰로 유도)
- 다시 만난 문장에 코멘트 이어 달기
- 문장 카드 이미지로 내보내기
- 자기 책을 직접 찍어 올려 표지로 쓰기 (해상도 문제가 근본적으로 사라짐)
- 노션 CSV 가져오기 (기본 계획은 손으로 다시 입력)

### 안 하는 것

태그, 독서 통계·연간 목표, 읽기 진행률(현재 페이지), 문장 OCR·사진 첨부,
공유·공개 기능, 소셜 기능, 알림.

## 3. 워딩과 톤

### 워딩

앱 전체의 언어는 **종이책을 다루는 손의 동작**에서 가져옵니다.

| 화면·상태    | 표기      | DB 값       |
| ------------ | --------- | ----------- |
| 네비게이션 1 | 책장      | —           |
| 네비게이션 2 | 밑줄      | —           |
| 상태         | 읽고 싶음 | `wishlist`  |
| 상태         | 읽는 중   | `reading`   |
| 상태         | 읽음      | `finished`  |
| 상태         | 덮어둠    | `set_aside` |

- '포기', '하차', '실패' 계열 단어는 쓰지 않습니다. 나만 보는 기록에
  스스로에 대한 판정을 붙이지 않습니다.
- 표기와 DB 값을 분리해두었으므로, 표기를 바꿀 때 마이그레이션이 필요 없습니다.
- 데이터 모델의 `passage`가 UI의 "밑줄"입니다.

### 톤앤매너

- 너무 세련되지 않은, 아날로그적인 질서. 종이와 오브제 질감을 살린 컬러웨이.
- 정연한 그리드. 시원함은 표지 크기가 아니라 **여백과 그리드**로 만듭니다 (§7 참조).
- 레퍼런스: 유어마인드(your-mind.com). 얇은 상단 네비 하나, 나머지는 전부 콘텐츠.
  섹션마다 배경 컬러 블록으로 리듬. 장식 없는 담백한 타이포.
  발췌문 + (쪽수) 표기 형식.
- **가져오지 않을 것:** 유어마인드의 불규칙한 배치. 남의 콘텐츠를 구경할 때는
  즐겁지만, 내 기록을 찾을 때는 위치가 예측 가능해야 합니다.

### 디자인 토큰

| 용도             | 값                                           |
| ---------------- | -------------------------------------------- |
| 문장용 세리프    | 마루 부리                                    |
| 본문·UI 산세리프 | IBM Plex Sans KR                             |
| 종이(배경)       | `#F7F4ED`                                    |
| 카드             | `#FFFDF8`                                    |
| 먹(본문)         | `#23211D`                                    |
| 보조 텍스트      | `#6B665C`                                    |
| 선               | `#DDD8CC`                                    |
| 밑줄             | `#57544D` (연필 흑연색)                      |
| 강조             | `#C4573A` (벽돌빛 주홍) — 쓸 자리 미정 (§10) |

- **순백과 순검정을 쓰지 않습니다.** 화면이 만들어내는 색이지 종이의 색이 아닙니다.
- **고정색은 최소로.** 책마다 `accent_color`가 들어오므로 앱 고정색이 많으면 충돌합니다.
- **추출한 색은 반드시 정규화합니다.** HSL로 변환해 명도를 88~~91%, 채도를 15~~30%로
  강제합니다. 이 규칙이 없으면 어떤 책은 새까맣고 어떤 책은 형광입니다.
  명도 상한을 91%로 잡은 건 시안에서 그보다 밝은 색이 종이색과 구분되지 않아서입니다.
- 색·활자·간격의 구체적인 값은 **`design.md`**에 있습니다. 이 문서는 무엇을
  만드는지, `design.md`는 어떻게 보이는지를 다룹니다.

### 모션

사람이 직접 손으로 움직이는 듯한, 투박하고 리듬감 있는 스톱모션 기법.

- **문장과 출처를 가르는 구분선 자리에 손으로 그은 밑줄이 놓입니다.** 문장 전체에
  긋지 않습니다 — 여러 줄일 때 선이 여러 개가 되고 마지막 줄이 짧으면 어중간하게
  끊깁니다. 이 자리에 두면 카드당 선이 정확히 하나이고, 모션도 한 번만 일어납니다.
- **매번 다른 파형을 그립니다.** 같은 path를 재사용하면 도장 찍은 것처럼 보입니다.
  대상 id를 시드로 삼아 결정적으로 생성합니다. 색은 `#57544D`, 대략 0.7초에 ease-out.
- `prefers-reduced-motion`을 존중합니다.

세부 규격은 `design.md`에 있습니다.

## 4. 데이터 모델

Postgres (Supabase). 모든 PK는 `uuid`.

### book — 공용 마스터

알라딘에서 받아온 사실 정보. 사용자별이 아니라 전역 공유입니다.

| 컬럼             | 타입        | 비고                                                |
| ---------------- | ----------- | --------------------------------------------------- |
| `id`             | uuid        | PK                                                  |
| `aladin_item_id` | text        | UNIQUE. 실질적 자연키                               |
| `isbn13`         | text        | nullable (독립출판·절판 대비)                       |
| `title`          | text        |                                                     |
| `author`         | text        | "홍길동 (지은이), 김철수 (옮긴이)" 형태 원문 그대로 |
| `publisher`      | text        |                                                     |
| `published_at`   | date        |                                                     |
| `cover_url`      | text        | 알라딘 원본 URL                                     |
| `cover_path`     | text        | Supabase Storage 경로                               |
| `cover_is_large` | boolean     | 큰 이미지 확보 여부 (§7)                            |
| `cover_width`    | int         | 표지 이미지 가로 px. nullable                       |
| `cover_height`   | int         | 표지 이미지 세로 px. nullable                       |
| `accent_color`   | text        | 표지에서 추출한 대표색                              |
| `page_count`     | int         | nullable                                            |
| `size_width`     | int         | 가로 mm. nullable                                   |
| `size_height`    | int         | 세로 mm. nullable                                   |
| `size_depth`     | int         | 두께 mm. nullable                                   |

| `style_desc`     | text        | 양장본·반양장본 등. nullable                        |

### shelf_item — 서재의 한 권

`user`와 `book` 사이의 조인 엔티티. 내 기록은 전부 이 아래로 모입니다.

| 컬럼                | 타입        | 비고                                              |
| ------------------- | ----------- | ------------------------------------------------- |
| `id`                | uuid        | PK                                                |
| `user_id`           | uuid        | FK → auth.users                                   |
| `book_id`           | uuid        | FK → book                                         |
| `status`            | text        | `wishlist` / `reading` / `finished` / `set_aside` |
| `status_changed_at` | timestamptz |                                                   |
| `started_at`        | timestamptz | nullable                                          |
| `finished_at`       | timestamptz | nullable                                          |
| `archived_at`       | timestamptz | nullable. 상태와 직교하는 축                      |
| `rating`            | int         | nullable. 1~5                                     |
| `created_at`        | timestamptz |                                                   |

`UNIQUE(user_id, book_id)`

### review — 책당 하나

| 컬럼            | 타입        | 비고                 |
| --------------- | ----------- | -------------------- |
| `id`            | uuid        | PK                   |
| `shelf_item_id` | uuid        | FK, **UNIQUE**       |
| `user_id`       | uuid        | FK                   |
| `body`          | text        | 마크다운 서브셋 (§6) |
| `created_at`    | timestamptz | 처음 쓴 날           |
| `updated_at`    | timestamptz | 마지막으로 고친 날   |
| `deleted_at`    | timestamptz | nullable             |

`shelf_item`에 컬럼으로 합치지 않는 이유: 리뷰 없는 책이 대부분이라
목록 조회 때마다 긴 텍스트를 끌고 다닐 필요가 없고, 통합 검색에서
세 테이블을 같은 모양으로 묶어야 하기 때문입니다.

### passage — 밑줄

| 컬럼            | 타입        | 비고                         |
| --------------- | ----------- | ---------------------------- |
| `id`            | uuid        | PK                           |
| `shelf_item_id` | uuid        | FK                           |
| `user_id`       | uuid        | FK                           |
| `body`          | text        | 원문 그대로. 서식 없음       |
| `page`          | int         | nullable                     |
| `last_shown_at` | timestamptz | nullable. 오늘의 밑줄용 (§6) |
| `created_at`    | timestamptz |                              |
| `deleted_at`    | timestamptz | nullable                     |

정렬: `page NULLS LAST, created_at`

### passage_comment — 밑줄에 단 생각

| 컬럼         | 타입        | 비고     |
| ------------ | ----------- | -------- |
| `id`         | uuid        | PK       |
| `passage_id` | uuid        | FK       |
| `user_id`    | uuid        | FK       |
| `body`       | text        | 평문     |
| `created_at` | timestamptz |          |
| `deleted_at` | timestamptz | nullable |

한 문장에 여러 개. 시간순으로 쌓입니다. 몇 년 뒤의 내가 같은 문장 아래에
다른 생각을 덧붙일 수 있어야 합니다.

### profile

`auth.users`를 직접 조인하지 않기 위한 표준 패턴. 가입 시 트리거로 생성.

| 컬럼           | 타입                    |
| -------------- | ----------------------- |
| `id`           | uuid PK = auth.users.id |
| `display_name` | text                    |
| `avatar_url`   | text                    |
| `created_at`   | timestamptz             |

### 공통 규칙

- `body`라는 컬럼명 통일은 의도적입니다. 통합 검색에서 세 테이블을
  `UNION ALL`로 묶을 때 쿼리가 깔끔해집니다.
- `review` / `passage` / `passage_comment`는 soft delete(`deleted_at`).
  UI에 휴지통을 만들 필요는 없고, 실수로 지운 기록을 SQL로 되살릴 수 있으면 됩니다.
  `shelf_item`은 hard delete.
- 모든 조회 쿼리는 `deleted_at IS NULL`을 포함합니다.

### RLS

**전부 켭니다.** 다중 사용자이므로 정책 하나가 잘못되면 남의 리뷰가 보입니다.

| 테이블            | 정책                                      |
| ----------------- | ----------------------------------------- |
| `book`            | 로그인 사용자 전체 read / insert / update |
| `shelf_item`      | `auth.uid() = user_id`                    |
| `review`          | `auth.uid() = user_id`                    |
| `passage`         | `auth.uid() = user_id`                    |
| `passage_comment` | `auth.uid() = user_id`                    |
| `profile`         | 본인 read / update                        |

## 5. 화면

### 라우트

```
/                 로그인 전 랜딩 · 로그인 후 /shelf로 (2차에 큐레이션 홈)
/shelf            책장
/shelf/[id]       책 상세
/underlines       밑줄
/archive          아카이브
/settings         설정
```

검색은 화면이 아니라 **어디서나 열리는 오버레이**입니다. 끝나면 원래 자리로 돌아옵니다.

### 랜딩

로그인하지 않은 사람이 보는 유일한 화면. 앱이 뭔지 3초 안에 보여주고
구글 로그인 버튼 하나. 가입 절차 없음.

### 책장 `/shelf`

- 상태 탭 4종 (읽고 싶음 / 읽는 중 / 읽음 / 덮어둠)
- **표지를 큼지막하게, 최대 4열로.** 상세·밑줄의 720 읽기 폭에 묶지 않습니다 —
  표지를 보러 오는 화면이라 표지를 크게 씁니다. **넓은 화면에서는 4권이 폭을 채우도록
  표지가 커지고, 좁아지면 2열·1열로 줄며 표지도 함께 작아집니다.** 셀 안에서 표지를
  **아래 기준선에 맞춰** 놓습니다. 규격은 `design.md` §표지 격자.
- 표지 크기는 **높이만 판형에서 가져오고 폭은 이미지 실제 비율로** 계산하되, 그 크기를
  **셀 폭에 비례**시켜 열 수에 따라 커지고 작아지게 합니다. 판형이 정하는 건 크기고,
  모양은 이미지가 정합니다.
- **오늘의 밑줄은 일단 뺐습니다** (사용자 지시, 2026-08-04). 표지를 크게 쓰면서 자리가
  애매해져, 넓은 책장에서 어떻게 보일지 정할 때까지 보류합니다.
- 문고본은 좁고 낮게, 크라운판은 높게, 사진집은 정사각형에 가깝게. 아래를 맞춰
  늘어서면 실제 선반에 꽂힌 책처럼 보입니다. 이 들쭉날쭉함은 무작위가 아니라
  책의 실물에서 나온 것이라, 유어마인드의 불규칙한 배치를 배제한 것과 모순되지
  않습니다. **격자는 정연하고 불규칙은 셀 안에서만 일어납니다.**
- 판형 데이터가 없으면 152 × 225mm를 기본값으로 씁니다.
- **판형 데이터를 그대로 믿지 않습니다.** 알라딘의 `sizeWidth` / `sizeHeight`는
  가로·세로가 뒤바뀐 채 오는 책이 있습니다 (표본 18권 중 5권. 세로로 긴 문고본이
  "가로 178 × 세로 110"으로 옵니다). 그대로 쓰면 그 책들은 실제보다 납작해집니다.
  **어느 값이 세로인지는 표지 이미지의 방향으로 판정합니다** — 이미지가 세로형이면
  판형의 큰 값이 세로, 가로형이면 작은 값이 세로입니다. 가로로 긴 책은 실재하므로
  그대로 두고(이미지도 가로형입니다), 잘못 들어온 값만 바로잡는 규칙입니다.
  정사각형에 가까운 사진집은 어느 쪽으로 계산해도 같습니다.
  알라딘이 준 값은 `book`에 원본으로 남기고 보정은 화면에서 합니다.
- 표지 아래 제목, 저자, **밑줄 개수**
- 맨 위에 **오늘의 밑줄** 한 장 (§6)
- 아카이브된 항목은 여기 나오지 않습니다

**빈 상태:** 검색창 말고 아무것도 두지 않습니다. 오늘의 밑줄 자리도 비웁니다.
여기서 뭘 해야 하는지 1초 안에 안 보이면 사용자는 나갑니다.

### 책 상세 `/shelf/[id]`

위에서 아래로: 표지와 책 정보 → 상태와 별점 → 리뷰 →
이 책의 밑줄 목록 → 밑줄 추가.

**책 정보로 보여주는 것:** 표지 · 제목 · 저자(지은이·옮긴이 등 원문 그대로) ·
출판사 · 쪽수 · 책 소개(알라딘 `description`, 한두 문단). 판형·무게·출간일·제본
형태는 `book`에 데이터로 두되 화면에는 내지 않습니다 — 책장 그리드가 쓰는 값이지
독자가 상세에서 읽을 정보가 아닙니다. (표지를 이 화면에서 얼마나 크게 쓸지는
§7에서 500px 표지가 가능해진 뒤로 다시 정할 수 있게 열려 있습니다.)

밑줄 추가는 스크롤과 무관하게 항상 닿을 수 있어야 합니다. 모바일에서
한 손으로 하는 동작입니다.

### 밑줄 `/underlines`

- **세로 한 줄로 흐릅니다.** 격자로 깔지 않습니다.
- **배경색을 책마다 다르게** 줍니다 (`book.accent_color`). 스크롤하다 색이 바뀌면
  책이 바뀐 것입니다.
- 카드 구성: 문장(마루 부리, 크게) → 문장 아래 손으로 그은 밑줄 → 얇은 구분선 →
  책 제목과 쪽수(작게, 산세리프) → 코멘트가 있으면 그 아래 날짜와 함께
- 상단에 **섞기** 버튼. 최신순으로만 보면 오래된 문장이 영영 밀려납니다.
- 문장 카드를 누르면 그 책의 상세로 갑니다. 밑줄 화면이 막다른 길이 되지 않게 하는 장치.

### 검색 오버레이

화면을 덮으면서 입력창에 커서가 들어가 있습니다.
검색 → 표지 누르기 → 상태 고르기 → 닫힘. 세 번의 탭.

**책을 담으면 목록으로 돌아가지 않고 그 책의 상세로 자동 이동합니다.**
방금 담은 책이 눈앞에 펼쳐지고 "밑줄 긋기"가 바로 보여야 합니다.

이미 서재에 있는 책은 "이미 서재에 있어요"로 안내합니다.

### 설정 `/settings`

계정, 데이터 내보내기(JSON), 계정 삭제. 남의 데이터를 받는 서비스이므로
최소한의 개인정보처리방침 링크가 필요합니다.

### 첫 방문자 여정

```
구글로 시작하기  →  빈 책장  →  책 검색해서 담기
                                      ↓
                  첫 밑줄 긋기  ←  책 상세 (자동 이동)
```

이 다섯 단계가 **2분 안에** 끝나야 합니다.

## 6. 규칙

### 상태 전이

- `reading`으로 바뀌면 `started_at`, `finished`로 바뀌면 `finished_at`을 찍습니다.
- **이미 값이 있으면 덮어쓰지 않습니다.** 덮어뒀다가 다시 읽어도 처음 시작한 날은
  그대로 남아야 합니다.
- 트리거가 아니라 애플리케이션 레이어에서 처리합니다.
- 아카이브는 상태와 별개입니다. "읽음이면서 아카이브됨"이 성립합니다.

### 별점

- **상태와 별점은 독립입니다.** 서로 아무것도 트리거하지 않습니다.
- 상태를 `finished`로 바꿔도 별점을 묻지 않습니다.
- 별점을 매겨도 상태가 바뀌거나 화면에 반응이 뜨지 않습니다. 조용히 저장만 합니다.
- 별점은 언제든 매기고 고칠 수 있습니다. `wishlist`인 책에 별점을 줘도 상태는
  그대로입니다.

> 예전에는 "완독으로 바꾸면 별점을 묻고, 첫 별점이 완독을 유발한다"는 연동이
> 있었습니다. 두 규칙이 서로를 부르는 고리라 다루기 번거롭고, 별점을 상태와
> 분리해 두는 편이 단순해서 걷어냈습니다.

### 오늘의 밑줄

- **하루 단위로 고정.** 새로고침할 때마다 바뀌면 우연이 아니라 슬롯머신입니다.
  `user_id` + 날짜를 시드로 결정적으로 뽑습니다.
- **오래 안 본 것 우선.** `last_shown_at`이 비어 있거나 오래된 것 중에서 고릅니다.
- **밑줄이 3개 미만이면 표시하지 않습니다.** 대신 "밑줄을 그어보세요" 안내.

### 리뷰 에디터

- 서식은 **리뷰에만** 있습니다. 밑줄은 원문이고 코멘트는 짧은 메모라 평문입니다.
- 지원: `**굵게**`, 줄바꿈. 그게 전부입니다.
  제목·소제목·불릿·구분선·인용 없음.
- 에디터 라이브러리를 붙이지 마세요. textarea에 굵게 버튼 하나.
- 재독 기록은 본문 안에서 줄을 띄우고 굵은 한 줄("2028년, 다시 읽음")로 나눕니다.

### 밑줄 입력

- **문장만 있으면 저장됩니다.** 쪽수와 코멘트는 선택입니다.
- 코멘트 입력란은 접힌 상태로 시작합니다.
- 문장을 타이핑하는 건 큰 노동입니다. 여기서 필수 항목을 늘리면 사용자가 이탈합니다.

## 7. 알라딘 TTB API

키 발급: blog.aladin.co.kr/openapi. 사이트 URL 등록 후 승인 필요.
하루 5,000회 제한.

**키는 서버에서만 씁니다.** `ALADIN_TTB_KEY`에 `NEXT_PUBLIC_` 접두사를 붙이지 마세요.
알라딘 엔드포인트가 `http://`라 브라우저에서 직접 호출하면 mixed content로도 막힙니다.
Next.js Route Handler를 경유합니다.

### 두 번 호출합니다

쪽수(`subInfo.itemPage`)가 검색 응답에 없고 상품 조회 API의 부가정보에만 있습니다.

| 시점           | 엔드포인트        | 용도                       |
| -------------- | ----------------- | -------------------------- |
| 검색할 때      | `ItemSearch.aspx` | 표지·제목·저자·출판사·ISBN |
| 서재에 담을 때 | `ItemLookUp.aspx` | 쪽수, 판형 등 상세         |

`book` 캐시가 있으므로 같은 책은 평생 한 번입니다. 병목은 검색 쪽이니
**같은 검색어의 결과를 몇 시간 캐시**합니다.

### 파라미터

두 호출 모두 `Version=20131101` **필수**. 기본값이 2007년 버전입니다.
`Output=JS`로 JSON을 받습니다.

- 검색: `QueryType=Keyword`, `SearchTarget=Book`, `Cover=Big`, `MaxResults=20`.
  한 페이지 최대 50개, 총 200개까지 조회 가능.
  `outofStockfilter`는 켜지 않습니다 — 절판된 책도 담아야 합니다.
- 조회: `ItemIdType=ItemId`, `OptResult=packing` (판형·무게·치수)

### 표지 — 500px를 받을 수 있습니다

**공식 `Cover` 파라미터의 최댓값 `Big`은 너비 200px입니다.** 여기까지가 문서에
적힌 사실이고, 오랫동안 이게 천장이라고 생각했습니다.

**실제로는 아닙니다.** 알라딘이 주는 이미지 URL의 경로 조각(`/cover200/`)을
`/cover500/`으로 바꾸면 **500×713px가 옵니다.** 세션 3에서 표본 18권 전부
성공했습니다. 문서에 없는 비공식 경로이므로 보장은 없지만, 실패해도 200px로
돌아가면 되므로 위험이 없습니다.

그래서 **표지를 크게 쓸 수 있습니다.** 레티나에서도 250px 슬롯까지 완전히
선명합니다. 원래 하고 싶었던 큰 표지가 가능해졌습니다.
구체적인 표시 크기는 `design.md`와 §5가 정합니다.

다만 이 앱의 주인공이 문장이라는 전제는 그대로입니다. 표지를 크게 쓸 수 있게
된 것이 "표지가 주인공"이 된다는 뜻은 아닙니다.

`/coverbig/`는 되지 않습니다 (404). 예전에 이 문서가 미검증으로 적어두었던
경로인데, 확인해보니 아닙니다. `/cover500/`입니다.

처리 방식:

1. 책을 담을 때 서버에서 `/cover500/`을 먼저 시도
2. 실패하면 알라딘이 준 URL(200px)로 폴백
3. 어느 쪽이 저장됐는지 `cover_is_large`에 기록
4. Storage에 복사하면서 대표색을 뽑아 `accent_color`에 저장

**200을 받았다고 큰 이미지인 것은 아닙니다.** 오래된 책에는 `/cover500/` 경로에
원본보다 **작은** 파일이 놓여 있습니다 — 『이해선 사진집』(592934)의 cover500은
150×155이고 cover200은 200×207입니다. 파일 크기로는 걸러지지 않으므로
**실제 픽셀 너비를 보고** 판단합니다 (300px 미만이면 폴백).

**표지 URL을 그대로 들고 있지 마세요.** 몇 년 뒤 깨집니다.

### 매핑

| 알라딘                       | book                                 |
| ---------------------------- | ------------------------------------ |
| `itemId`                     | `aladin_item_id`                     |
| `isbn13`                     | `isbn13`                             |
| `title`                      | `title`                              |
| `author`                     | `author` (파싱하지 않고 원문 그대로) |
| `publisher`                  | `publisher`                          |
| `pubDate`                    | `published_at`                       |
| `cover`                      | `cover_url`                          |
| `subInfo.itemPage`           | `page_count`                         |
| `subInfo.packing.sizeWidth`  | `size_width`                         |
| `subInfo.packing.sizeHeight` | `size_height`                        |
| `subInfo.packing.sizeDepth`  | `size_depth`                         |
| `subInfo.packing.weight`     | `weight`                             |
| `subInfo.packing.styleDesc`  | `style_desc`                         |
| 전체                         | `raw`                                |

`aladin_item_id` 기준 upsert.

### 검증 항목 — 세션 3에서 끝났습니다

1. **`OptResult=packing`은 별도 협의 없이 동작합니다.** 표본 18권에서 판형 결측
   0건. §5 책장 그리드의 전제가 성립합니다.
2. **검색 응답에 `itemId`가 옵니다.** `isbn13`·`cover`도 함께.
3. **`/coverbig/`는 404입니다. `/cover500/`이 됩니다** (위 "표지" 참조).

덧붙여 알게 된 것:

- **엔드포인트가 `https://`로 응답합니다.** 위에 적은 mixed content 이야기는
  낡았습니다. 키 때문에 서버 경유는 여전히 필요합니다.
- **`sizeWidth`와 `sizeHeight`가 뒤바뀐 채 오는 책이 있습니다.** 표본 18권 중 5권.
  §5의 "판형 데이터를 그대로 믿지 않습니다"에 규칙으로 적었습니다.
  매핑은 원문 그대로 저장하고 보정은 화면에서 합니다.

### 쓰지 않는 것

알라딘은 "책속에서" 인용구(`phraseList`)를 쪽수와 함께 최대 3개 제공합니다.
형식이 우리 밑줄과 똑같지만 **쓰지 않습니다.** 남이 고른 문장이 내 밑줄 사이에
섞이면 이 앱의 전제가 무너집니다.

## 8. 통합 검색 (2차)

### 범위

책(제목·저자)과 기록(리뷰·밑줄·코멘트)을 **둘 다 찾되 결과를 나눠서** 보여줍니다.

- 위: 책 — 표지가 있어 시각적으로 저절로 구분됩니다
- 아래: 기록 — 리뷰인지 밑줄인지 코멘트인지 작은 표시를 붙입니다

결과에서 밑줄을 누르면 그 문장이 있는 책 상세로, 책을 누르면 책 상세로 갑니다.

### 구현

세 테이블을 `UNION ALL` 뷰로 묶습니다. 컬럼명이 `body`로 통일되어 있어
쿼리가 단순합니다. `deleted_at IS NULL` 필수.

**한국어 검색은 Postgres 기본 전문검색으로 안 됩니다.** 기본 파서가 공백으로 단어를
자르는데 한국어는 조사가 붙어 "문장을"과 "문장이"가 다른 토큰이 되고,
띄어쓰기 없는 말은 쪼개지지 않습니다.

해법은 **PGroonga** — Groonga 검색 엔진을 Postgres 인덱스로 쓰는 확장이고,
Supabase 대시보드 Extensions에서 켤 수 있습니다. 기본 토크나이저 `TokenBigram`이
텍스트를 두 글자씩 잘라 색인하므로 조사·띄어쓰기와 무관하게 부분 일치가 됩니다.

```sql
create extension pgroonga;
create index passage_body_idx on passage using pgroonga (body);

select * from passage where body &@~ '문장';
```

**다만 개인 규모에서는 급하지 않습니다.** 문장이 수천 개면 `ILIKE '%검색어%'`로
전체를 훑어도 느리지 않습니다. 확장은 켜두고, 느려지면 인덱스를 붙이면 됩니다.
인덱스라서 나중에 추가해도 마이그레이션이 아닙니다.

## 10. 미해결

- **리뷰에서 무엇을 발췌할 것인가.** 2차 큐레이션 홈에서 리뷰를 보여줘야 하는데,
  리뷰는 긴 글 하나라 앞 세 줄을 자르면 대개 어색합니다. 한 줄 요약 필드를 두는 게
  정공법이지만 지금 넣으면 안 쓰는 필드가 됩니다.
- **판형 데이터의 결측률.** §5 책장 그리드가 실제 판형 비율에 기대고 있는데,
  값이 없는 책이 많으면 기본값 투성이가 되어 아이디어가 죽습니다. 실제 데이터로
  확인해야 합니다.
- **주홍(`#C4573A`)을 어디에 쓸 것인가.** 밑줄 기본색은 흑연으로 정했고, 주홍은
  오늘의 밑줄·저장 완료 반응 같은 "특별한 순간"에 쓰는 방향을 검토 중입니다.
  역할이 정해지기 전에는 쓰지 마세요.
- **노션 이관 방식.** 기본은 손으로 다시 입력(다시 읽게 되니 나쁘지 않음).
  너무 힘들면 CSV 가져오기.
