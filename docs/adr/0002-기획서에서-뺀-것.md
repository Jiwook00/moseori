# 0002 — 기획서 §5·§6에서 의도적으로 뺀 것

상태: 채택. **기획서 본문 back-port는 보류.**

## 맥락

기획서는 사람이 쓰는 초기 명세다. 만들면서 사용자 결정으로 몇 가지를 뺐는데,
기획서 본문은 아직 그대로다. 코드·design.md와 기획서가 어긋난 상태를 여기 모은다.

## 결정 (뺀 것)

- **밑줄 추가 하단 고정** (§5 "스크롤과 무관하게 항상 닿기") → 목록 끝 흐름에 둠.
  하단 고정이 "어지럽고 복잡"하다는 판단.
- **책 소개(`description`) 상세 표시** (§5 "책 정보로 보여주는 것"에 포함) → 표시 안 함.
  데이터(`book.description`)는 담아서 보존.
- **판형·무게·출간일·제본** (§5) → 화면에 내지 않음. "애초에 잘못된 결정". 데이터는 보존.
- **오늘의 밑줄 안내 문구** (§6, 밑줄 3개 미만 시) → 안내 대신 아무것도 안 보임.
- **밑줄 섞기 버튼** (§5) → 넣지 않음.
- **별점–완독 연동** (§6) → 걷어내고 별점과 완독을 **독립**으로.

각 항목의 현행 규격은 `design.md`. 이 목록은 `progress.md` "문서와 어긋난 것" 표에도
한 줄씩 살아 있다.

## 결과

기획서 §5·§6 본문이 실제와 어긋난 채로 남아 있다. 다음에 기획서를 일괄 정정하거나,
의도적으로 남길지 결정해야 한다. (예: `review` UNIQUE는 "살아있는 리뷰 기준"으로 문구
정정 보류 중 — 표 참조.)
